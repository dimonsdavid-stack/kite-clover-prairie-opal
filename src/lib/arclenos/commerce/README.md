# ARCLENOS x402 commerce

Seven TanStack HTTP routes: GET opportunities, atlas and pricing; POST intelligence/brief, simulate, security/review and factory/preview. POST JSON is `{opportunityId}` for a brief and `{composition}` for the other paid services. Composition is runtime validated. Briefs are sourced deterministic factor analyses, not fabricated AI output. Factory previews explicitly report absent executable calldata until versioned deployment configuration exists.

Protocol: official `@x402/core@2.27.0` HTTPFacilitatorClient, x402 v2 `PAYMENT-REQUIRED`, `PAYMENT-SIGNATURE`, `PAYMENT-RESPONSE`, exact EIP-3009, `eip155:8453`, native Base USDC. Only configured facilitators advertising this pair are accepted. Sources verified during implementation:
- https://github.com/x402-foundation/x402/blob/main/specs/x402-specification-v2.md
- https://github.com/x402-foundation/x402/blob/main/typescript/packages/core/src/http/httpFacilitatorClient.ts

Required secure environment: DATABASE_URL, ARCLENOS_TREASURY_ADDRESS, ARCLENOS_PUBLIC_ORIGIN (HTTPS), X402_FACILITATOR_URL (HTTPS), BASE_RPC_URL (HTTPS), ARCLENOS_INTERNAL_PAYER_ADDRESSES (comma-separated founder and other internal wallets). Optional X402_FACILITATOR_BEARER supports facilitator deployments accepting a managed bearer token; CDP JWT credentials require an auth adapter and must not be represented as a static token. Apply migration 0005 explicitly before enabling. No live-money operation has been performed by these tests.

Payment authorization identity is network/token/payer/nonce, so re-encoding headers cannot bypass durable uniqueness. Request method, canonical URL, canonical body and SKU are hashed into request correlation; a proof cannot buy different inputs. A hashed signature additionally binds retry access; raw signatures are never persisted. The durable unique insert arbitrates concurrent instances. Fulfillment output is computed before settlement and persisted; a paid retry returns that same output without re-executing the service. A second transfer with the same transaction is blocked by a unique successful transaction index (retained even after refunds).

A timeout after submitting settlement is **indeterminate** and never automatically resubmitted. `reconcileCommerce()` checks previously persisted successful settlement transactions using independent Base RPC receipts, matching USDC Transfer amount/from/to and canonical safe blocks. Uncertain requests with no known transaction hash require operator-supplied chain evidence; no blind settlement retry exists. Call this bounded function from the authorized durable scheduler. A crash before settlement may leave a PENDING record; operator reconciliation must establish absence of transfer before allowing a new authorization. Safety takes precedence over automatic duplicate charging.

Receipt transition, revenue insertion and valid referral conversion increment are one SQL statement/transaction. Self/internal payments are stored with economic_valid=false, not realized revenue. Referral codes are untrusted marketing attribution, never payout authority. Gross USDC is exact numeric atomic units; net and network costs remain NULL until cost/fee reconciliation, never falsely zero. No automated referral payout is implemented. Founder/internal wallet allowlist must remain complete for economically valid reporting.

Limitations: deterministic security scans are configuration reviews, not deployed contract audits. The initial factory preview service provides composition/simulation/security but not executable deployment calldata until the separate deployment registry is connected. The paid routes fail closed when deployment configuration is incomplete. Production facilitator, database and funded client wallet are required to commission and verify the real commercial funnel.

Tests: `node --experimental-strip-types --test src/lib/arclenos/commerce/core.test.ts`. Injected facilitator/RPC tests do not constitute live settlement evidence.
